Peering policy

Open, but rigorous.

We're happy to peer with any network holding a valid ASN and up-to-date routing objects. In return, we apply strict ROA-based filtering.

  • Valid ASN

    A registered, routable autonomous system number is required for any peering session.

  • Accurate route object

    Your prefixes must be declared with an accurate, up-to-date route object (IRR), consistent with what you announce.

  • Basic filtering and prefix limits

    Basic filtering and prefix limits are applied on both sides of the session, without exception.
